# v0.3 Wear Physical Acceptance Gate

This is the permanent acceptance record and reusable checklist for the `v0.3` physical phone,
Wear app, and watch-face gate on a Samsung Galaxy Watch8 non-Classic. It validates the existing
phone-owned Wear Data Layer path; it does not authorize new coaching behavior or a new glucose
provider.

The implementation, coaching behavior, and production scope remain frozen during this gate.
`v0.4` work must not begin until this document records an accepted run. A passing engineering gate
does not make a debug-signed build production-ready or suitable as a medical device, glucose alarm,
or replacement for the CGM vendor application.

## Status vocabulary

Use exactly one status for every checklist item:

- `PASS`: the pinned build produced the predeclared expected result and retained acceptable evidence.
- `FAIL`: the test ran and the result differed from the predeclared expectation.
- `BLOCKED`: the test could not produce a valid result because a prerequisite, device, environment,
  or observable acceptance criterion was unavailable.
- `NOT RUN`: no valid attempt has been made against the pinned build.

Never use `PASS` for a partial run, an inference, an emulator result, or an observation from a
different artifact. Comments such as "looks good" do not replace a status or evidence.

## Strict gate rules

The gate is `ACCEPTED` only when:

1. the `v0.2` phone-first live Nightscout acceptance prerequisite is linked and passed;
2. every required item in this document is `PASS` against one pinned artifact set;
3. no required item is `FAIL`, `BLOCKED`, or `NOT RUN`;
4. the final artifact, device, configuration, timing, and evidence fields are complete; and
5. the final reviewer signs the result below.

Any required `FAIL`, `BLOCKED`, or `NOT RUN` means the gate is not accepted. `NOT RUN` keeps the
decision pending; an attempted required check that cannot run or pass makes it blocked. Stop before
`v0.4`, record sanitized failure evidence, correct any issue in a separate implementation change,
rebuild and repin the artifacts, and rerun every affected test. A source, dependency, manifest,
resource, signing, or APK change invalidates the pinned run. A settings change invalidates every
result that depends on that setting. Do not combine passing rows from incompatible builds or
configurations.

## Evidence privacy

Acceptance evidence must not contain actual glucose values, raw health history, personal
Nightscout URLs, credentials, tokens, names, exports, or other identifying health data. Use a
synthetic/test server when possible.

Permitted evidence includes artifact hashes, signing-certificate hashes, package/version metadata,
non-sensitive revision identifiers, elapsed durations, categorical value-match results, device and
OS versions, redacted logs, and screenshots with every health value and identifier masked. A
`FAIL` or `BLOCKED` still requires useful sanitized evidence; privacy is not a reason to omit the
artifact, device, timestamp, step, expected result, and categorical failure description.

Store evidence at the predeclared location below. Do not commit unsanitized `logcat`, bug reports,
screenshots, or exports to the repository.

## Initial synchronization

Compare state categorically without retaining actual health values. For each test, record whether
glucose, trend, delta, timestamp/update age, activity fields, recommendation state, and complication
state match the phone-authored normalized state where those fields are expected. Record measured
delay and the non-sensitive phone revision when available.

"App not open" means the relevant UI is not foregrounded; it does not mean Android force-stop.
Force-stop is a separate lifecycle condition and must not be used to simulate ordinary background
delivery.

Run `SY-01` immediately after installation and face selection, before the Wear app UI has been
manually opened for the first time. Then run the open-app cases in order. If the Wear UI was opened
before `SY-01`, the first-background-delivery result is invalid and must be repeated from a fresh
pinned Wear installation state.
